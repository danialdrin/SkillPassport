# Feature Specification: Gemini API Migration

**Feature Branch**: `002-gemini-api-migration`

**Created**: 2026-09-04

**Status**: Draft

**Input**: User description: "change the omniroute api with gemini api key go through all the files to change the omniroute to gemini api key use a best free model for this project"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Developer Configures Gemini API Key (Priority: P1)

A developer wants to replace the OmniRoute proxy service with a direct Gemini API key so that LLM-powered features (strong analysis, interactive modules, quizzes, flashcards, summaries) work without requiring a locally running OmniRoute proxy.

**Why this priority**: This is the foundational change — without it, no LLM feature works in deployment environments where OmniRoute is not available.

**Independent Test**: Can be fully tested by setting a valid `GEMINI_API_KEY` environment variable, restarting the backend, and verifying that the `/resources/{id}/summary` endpoint returns a valid AI-generated response.

**Acceptance Scenarios**:

1. **Given** a valid `GEMINI_API_KEY` is set in `.env`, **When** the backend starts, **Then** the LLM service initialises successfully using the Gemini API without any OmniRoute configuration.
2. **Given** `GEMINI_API_KEY` is missing or empty, **When** the backend starts, **Then** a clear startup warning/error is logged indicating the API key is required.
3. **Given** a valid `GEMINI_API_KEY`, **When** any LLM-dependent endpoint is called (summary, flashcards, quiz, strong analysis), **Then** the response is generated by the Gemini model, not OmniRoute.

---

### User Story 2 - Platform Uses Best Free Gemini Model (Priority: P2)

The platform selects `gemini-2.0-flash` (Google's best free-tier model) as the default model for all LLM calls, providing high-quality responses within the free API quota.

**Why this priority**: Model selection directly affects response quality and API cost. Using the best available free model maximises value without incurring charges.

**Independent Test**: Can be verified by inspecting the model name used in API request logs or by confirming the config setting resolves to `gemini-2.0-flash`.

**Acceptance Scenarios**:

1. **Given** no `GEMINI_MODEL` override is set, **When** the LLM service makes a request, **Then** it uses `gemini-2.0-flash` by default.
2. **Given** a `GEMINI_MODEL` override is set in `.env`, **When** the LLM service makes a request, **Then** it uses the specified model.

---

### User Story 3 - All OmniRoute References Are Removed (Priority: P2)

All code, configuration, documentation, and environment variable references to OmniRoute are replaced or removed so the codebase no longer depends on or mentions the OmniRoute service.

**Why this priority**: Clean migration eliminates confusion for future developers and ensures no hidden OmniRoute dependencies remain.

**Independent Test**: A text search for "omniroute" (case-insensitive) across all project source files returns zero matches in active code files (.py, .env, config files).

**Acceptance Scenarios**:

1. **Given** the migration is complete, **When** a search for `OMNIROUTE` is performed across all `.py` files, **Then** no matches are found.
2. **Given** the migration is complete, **When** a search for `OMNIROUTE` is performed in `config.py` and `.env`, **Then** no matches are found.
3. **Given** the migration is complete, **When** log messages are inspected during LLM service calls, **Then** all references say "Gemini" not "OmniRoute".

---

### Edge Cases

- What happens when the Gemini API rate limit is hit during analysis? The system should propagate a meaningful error to the job status rather than silently failing.
- What happens when a request payload exceeds Gemini's token limits? Chunking already exists; the spec assumes it remains sufficient.
- How does the system handle an invalid `GEMINI_API_KEY` at runtime? A logged error with an appropriate HTTP 500 or job-failed status should be returned.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST replace the `OMNIROUTE_API_KEY`, `OMNIROUTE_BASE_URL`, and `OMNIROUTE_MODEL` environment variables with `GEMINI_API_KEY` and `GEMINI_MODEL`.
- **FR-002**: System MUST update `app/core/config.py` to define `GEMINI_API_KEY` and `GEMINI_MODEL` settings, removing all OmniRoute-named settings.
- **FR-003**: System MUST update `app/services/llm_service.py` to use the Google Gemini SDK instead of the OpenAI-compatible AsyncOpenAI client pointed at OmniRoute.
- **FR-004**: The default value of `GEMINI_MODEL` MUST be `gemini-2.0-flash` (the best available free-tier Gemini model).
- **FR-005**: System MUST update `.env` to remove OmniRoute keys and add `GEMINI_API_KEY` and `GEMINI_MODEL`.
- **FR-006**: System MUST update `app/main.py` API description to remove OmniRoute mentions and reflect Gemini usage.
- **FR-007**: System MUST update log messages in `llm_service.py` to reference "Gemini" instead of "OmniRoute".
- **FR-008**: System MUST update `requirements.txt` to include the `google-generativeai` package and remove any OmniRoute-specific dependency if present.
- **FR-009**: All inline code comments referencing OmniRoute (e.g., in `interactive.py`) MUST be updated to reference Gemini.
- **FR-010**: System MUST ensure all existing LLM-using endpoints (summary, flashcards, quiz, strong analysis) continue to function identically after migration.

### Key Entities

- **LLM Service** (`llm_service.py`): Central LLM call handler — changes here affect all AI-powered features.
- **Config** (`config.py`): Source of truth for API credentials and model selection — drives `.env` variable names.
- **Environment** (`.env`): Runtime secrets file containing the actual Gemini API key value.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: All LLM-powered features (summary, flashcards, quiz, strong analysis) return valid responses when tested with a real `GEMINI_API_KEY`, with no OmniRoute proxy running.
- **SC-002**: Zero occurrences of the string "omniroute" (case-insensitive) in any `.py` source file after migration.
- **SC-003**: Zero occurrences of `OMNIROUTE_` prefix in `.env` and `config.py` after migration.
- **SC-004**: The default model resolves to `gemini-2.0-flash` when no override is provided, verifiable by inspection of config defaults.
- **SC-005**: The backend starts without errors when `GEMINI_API_KEY` is properly set and no OmniRoute service is running.

## Assumptions

- The project will use the `google-generativeai` Python SDK to call the Gemini API directly.
- `gemini-2.0-flash` is the best free-tier model available for this project's use case (educational content analysis, structured JSON generation).
- The existing chunking logic in `strong_analysis_service.py` is adequate for Gemini's token limits and does not need restructuring.
- The user will supply their own `GEMINI_API_KEY` obtained from Google AI Studio (https://aistudio.google.com).
- Only the backend Python files and configuration are affected; no frontend changes are required.
- Existing JSON extraction logic (`json_extract`) remains compatible with Gemini response formats.
